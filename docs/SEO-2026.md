# International SEO implementation

## What changed

The previous language switcher changed visible text on a single English URL. The production build now creates a stable URL per supported language:

- English: `/`, `/bordeaux/`, `/tours/bordeaux-wine-food-history-walk/`
- French: `/fr/`, `/fr/bordeaux/`, `/fr/tours/bordeaux-wine-food-history-walk/`
- Spanish: `/es/`, `/es/bordeaux/`, `/es/tours/bordeaux-wine-food-history-walk/`

The existing `data-lang` translations, client widgets and EN/FR/ES controls remain. Language controls become ordinary links during the build, so they work without JavaScript. On a localized URL its language is visible in the delivered HTML. Saved browser preferences never override that URL. Existing English URLs remain valid, with normalized trailing slash canonical URLs. No new language proficiency is claimed.

`npm run build` runs a clean Astro build followed by `scripts/localize.mjs`. The postprocessor only selects public pages rendered through Layout. It never reads or rewrites private playbook content. The clean step prevents stale Astro output from mixing with localized pages during repeated builds. Do not remove the postprocessing step from Cloudflare's build command.

## Search metadata and content

- Native English, French and Spanish titles, descriptions, Open Graph and Twitter metadata.
- Tour titles include the destination where it was previously missing, using the existing translated tour titles.
- Self canonical URLs and reciprocal EN/FR/ES/x-default hreflang links.
- One public sitemap with 60 localized pages plus the two existing public games. Private pages are excluded.
- Stable Organization, Person and WebSite identities, localized WebPage and TouristTrip descriptions, localized destination lists and breadcrumbs. No invented shop address, opening hours, rating totals or self review stars are added.
- A useful Bordeaux planning section links existing food, wine, market, history, bicycle and personalised experiences. Cheese is mentioned where already included in the market tour. No unrelated cream or generic keyword pages are manufactured.
- Existing photographs get responsive WebP delivery copies with width, height and srcset. The 41 source images selected by these public pages are retained. Largest delivery variants total 41% fewer bytes than their corresponding original files; this is not a Core Web Vitals score or measured traffic improvement.

## Files and responsibilities

- `src/lib/seo.ts`: translated public page metadata and shared public business identity.
- `src/layouts/Layout.astro`: metadata, business graph, current language and switching behavior.
- `scripts/localize.mjs`: static language output, localized links/schema and sitemap.
- `scripts/images.mjs`: delivery image derivatives generated in `dist/assets/optimized` only.
- `scripts/clean.mjs`: removes disposable `dist` before building.
- `scripts/seo.test.mjs`: output regression checks.
- `src/components/BordeauxPlanning.astro`: relevant visitor planning content in three languages.
- `src/pages/bordeaux.astro`: includes the planning section.
- `src/pages/tours/[slug].astro`: translated tour metadata and hero alt attributes.
- `src/components/TourCard.astro`: translated image alt attributes.
- `src/components/TourFinder.astro`, `public/chat.js`: read the URL's document language for recommendations and FAQ UI.
- `package.json`, `package-lock.json`: build commands and direct build dependencies Cheerio and Sharp.
- `CLAUDE.md`: updated language architecture documentation.

No changes to original photos, factual tour collection files, prices, schedules, review quotations/attribution, private files, games or the canonical domain.
